## 设计要点（与篇 1 正文对齐）

| 层 | 要表达什么 |
| --- | --- |
| 顶栏 | **纪律包续篇 · 篇 1**；副标「从 OOP 到本体 · 形式语义支撑 AI 协作方法论」 |
| 上层左 | **已发方法论**（双轨 · ICV · Epic）小圆角条，细箭头向下 |
| 上层右 | 可选角标极小字「先读地图与卷三 · 见正文 §0」 |
| 中层左（语义层） | **协作本体** 大圆角块：「类 · 关系 · 公理 · 状态」；内嵌 4～5 个小节点标签「Epic · 任务单 · 阶段 · 审查 · 审批闸」用细线相连（概念图，非详细流程图） |
| 中层右（实现层） | **命令式实现** 大圆角块：「安装 · 同步 · 闸检查 · CI」；配闸门/齿轮/盾牌小图标；**向上粗箭头** 标注「服从本体约束」指向左侧本体块 |
| 中层底 | **ICVO 四标签** 横排四枚小卡：「Inform · Constrain · Orchestrate · Verify」；上方极小字「SDD 内 · 编排与验证分表」；**Orchestrate** 与 **Verify** 之间用虚线分隔，避免画成与 Inform 完全平级的第四套方法论 |
| 下层 | **文件实例** 暖灰横条：「任务单 · 审查 · 图谱 · 配置」；从本体块与实现块各有一条箭头汇入；底缘可选细字「本轮交付依据在文件 · 图与事件为可选增强」 |

**禁用**：具体产品仓库名、npm 安装步骤、LangChain/品牌 Logo、OWL 推理机广告感、金样板、invoke、关账摘要、AB 实验数字、真人照片。

**勿与正文 Mermaid 逐像素一致**：封面传达 **方法论 → 本体形式化 → 实现服从语义 → 文件实例落地** 一条链即可。
